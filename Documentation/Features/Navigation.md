# Navigation

Source: `Shared/ArcadiaCore/src/navigation.rs`  
Platform: all (single implementation rendered by OpenFrame on desktop and iOS)

---

## Overview

All navigation structure is declared in `navigation.rs` as static data. The GUI never hardcodes page IDs, group memberships, or settings hub structure — it reads from the registry. This means adding a new page or group requires only a registry edit; no render-path changes.

---

## Data types

### `NavigationPageDefinition`

| Field | Type | Purpose |
|-------|------|---------|
| `id` | `&'static str` | Stable dot-namespaced identifier e.g. `"utility.shell"` |
| `title` | `&'static str` | Display name |
| `description` | `&'static str` | Subtitle shown in hub views |
| `glyph` | `&'static str` | Icon key → `icon_path()` in `theme/icons.rs` |
| `system_image` | `&'static str` | SF Symbol name for iOS native contexts |
| `accent` | `&'static str` | Accent palette key for selected fill + icon tint |
| `required_module` | `Option<&'static str>` | Module name; page hidden when module disabled. `None` = always visible. |

### `NavigationGroupDefinition`

| Field | Type | Purpose |
|-------|------|---------|
| `id` | `&'static str` | Stable group identifier e.g. `"utilities"` |
| `label` | `&'static str` | Sidebar section header label |
| `glyph` | `&'static str` | Group icon key |
| `system_image` | `&'static str` | SF Symbol for iOS |
| `pages` | `&'static [&'static str]` | Ordered list of page IDs in this group |
| `accent` | `&'static str` | Group accent palette key |

## Visibility rule

Page visibility is derived entirely from `required_module`:

```rust
// GOOD — derive from page's declared required_module
let Some(page) = navigation::page_by_id(page_id) else { return false };
match page.required_module {
    Some(module_name) => is_module_enabled(module_name),
    None => true,
}
```

The Services page (`utility.services`) is an exception: it is service-driven. Its visibility is determined by whether any `ServiceDefinition` in `SERVICE_DEFINITIONS` has its `required_module` enabled, regardless of the page's own `required_module` field.

---

## Services-driven pages

`NavigationRegistryOwned::page_has_services(page_id)` returns true when at least one service in `SERVICE_DEFINITIONS` references that page ID. The GUI checks this to decide whether to show the page regardless of module state.

---

## `NavigationRegistryOwned`

A fully owned (heap-allocated) version of the registry, serializable to JSON. Generated by `NavigationRegistryOwned::from_registry()` which:

1. Copies static `PAGE_DEFINITIONS` → `Vec<NavigationPageOwned>`.
2. Appends extension nav pages from `python_registry`.
3. Copies `GROUP_DEFINITIONS` → `Vec<NavigationGroupOwned>`.
4. Copies special lists.
5. Appends service rows for each active service.

This value is emitted in `surface.snapshot.extra.navigation_registry` so thin clients can use the host's navigation structure.

## Adding a new page

1. Add a `NavigationPageDefinition` to `PAGE_DEFINITIONS` in `navigation.rs`. Set `required_module` if gated on a module.
2. Add the page ID to the appropriate group's `pages` slice, or to `SETTINGS_HUB_PAGE_IDS` / `GLOBAL_PAGE_IDS` / `TOP_BAR_PAGE_IDS`.
3. Implement the panel under `Desktop/src/gui/app/` (one implementation, renders on desktop and iOS).
4. Route content in the surface content switch — derive visibility from `required_module`; do not add a hardcoded match arm.

---

## Anti-patterns

```rust
// BAD — hardcoded page content dispatch grows with every new page
if self.active_page_id == "utility.shell" { … }
else if self.active_page_id == "global.modules" { … }

// GOOD — use the registry to drive dispatch; new pages need no edit here
let page = navigation::page_by_id(&self.active_page_id);
// render content based on page.id pattern matched against known panel types
```
